## Render 渲染

### React 渲染在过去十年的演变

#### 第一阶段：react 客户端渲染 CSR（Client Side Render）

![image-20250813下午124448174](https://raw.githubusercontent.com/zyileven/image-hosting-platform/master/src/2025/08/13/d1e23c71479c83b1a0816463cee060cc-image-20250813下午124448174-f775ff.png)

客户端渲染，指的是一开始请求，只获取到一个简单的 html 文件，然后开始加载核心 JS 的 bundle 包，等 js 加载完成之后，再在客户端的浏览器中构建整个页面。

**缺点：**

- SEO 效果差
  - 因为初始的 html 只有一个 div 标签
  - 当你有很多嵌套组件进行 API 调用时，主要内容区域可能加载较慢
- 性能和用户体验
  - 在达到 Interactive UI 阶段前，用户只能看见一个空白的页面
  - 随着功能越来越多，JS 的 bundle 包也会越来越大，加载时间就更长了



#### 第二阶段：服务端解决方案

![image-20250813下午125839114](https://raw.githubusercontent.com/zyileven/image-hosting-platform/master/src/2025/08/13/50d73d347392121c3551c05ea3ce43af-image-20250813下午125839114-1e21c7.png)

**好处：**

- SEO 优化
  - 因为服务端生成了有内容 HTML 文件，可以方便搜索引擎进行搜索
- 用户体验优化
  - 随着初始返回的 HTML 是有内容的，即使是还不能交互，但是用户依旧能看到相应的内容



**水合：**

在水合过程中，React在浏览器中控制并在内存中重建组件树，使用服务器端呈现的HTML作为蓝图，仔细地绘制出所有交互元素应该放在哪里，然后连接JavaScript逻辑。这包括初始化应用程序状态，添加单击和鼠标经过处理程序，以及设置完整的交互式用户体验所需的所有动态特性



**服务端解决方案**

- 静态站点生成 Static Site Generation（SSG）

  SSG 发生在当你准备把项目发布到服务器的构建时，这将生成已经渲染并准备好服务的页面，非常适合那些保持相对稳定的内容

- 服务端渲染 Server-Side Rendering（SSR）

  SSR 服务端渲染将会在用户请求时按需加载渲染，非常适合个性化的内容。

  服务端渲染与客户端渲染相比有了很大的进步，提供了更快的初始页面加载和更好的 SEO



 **缺点：**

1. 必须加载完页面所需的全部数据

   使用 Suspense 可以解决这个问题，通过使用 Suspense 包裹请求时间特别长的接口的模块，确保其他模块可以先完成渲染和水合，而当前模块等加载完成之后再显示。

2. 必须加载完页面所需的全部 JS

3. 必须等待水合完全部页面，才能进行交互

   使用代码拆分（Code Splitting）可以解决这个问题，他告诉你的 bundler 这块代码并不紧急，将他们分割到一个独立的块中

   使用 React.lazy 将代码拆分到一个独立的块中，这意味着浏览器可以独立下载 React 主代码和其他块代码。

#### 第三阶段：服务端组件（RSC React Server Components）

在此之前，我们见证了 React 在渲染上的发展：CSR → SSR → Suspense for SSR

但是我们依旧存在一些挑战：

- 用户需要下载过大的 JS 包
- 一些不必要的水合导致交互延迟
- 繁重的客户端处理导致性能下降

而 RSC 就是用来解决这些问题的。

该架构引入了双组件模型：

- Client Components 客户端组件
- Server Components 服务端组件

这种设计不是基于组件的功能，而是基于他们的执行环境以及他们设计用于交互的特定系统。

##### 客户端组件

就是在 RSC 架构出现之前的普通 React 组件。

客户端组件一般在客户端渲染（CSR）也可以在服务端渲染（SSR）为 HTML ，允许用户立即看到 HTML 内容而不是空白页面。

总的来说，客户端组件主要在客户端环境运行，但是如果你相对其进行优化，你也可以在服务端上运行一次。

**独有特点**：客户端组件可以访问客户端的所有环境（浏览器 API，监听，地理位置，本地存储），而服务端组件不行



##### 服务端组件

一种专门设计用于操作的新型 React 组件，代码保留在服务器上，永远不会下载到客户端。

##### 服务端组件的好处

- **捆绑包体积更小**：因为代码在服务器上，包括代码的依赖项也是，所以客户需要加载包更小了
- **直接访问服务器资源**：服务端组件由于是在服务器上，所以能够直接与服务端资源进行通信，利用服务端的功能和与数据源的接进性来管理计算密集型渲染任务。
- **安全性提升**：由于服务端组件在服务器上运行，所以用到的敏感数据 API keys 或者 tokens 这类的信息不会出现在客户端。
- **数据获取更加智能**：服务端组件允许你将数据获取移动到更靠近数据源的服务器，通过减少获取数据所需时间和客户端需要发出的请求数量来提高性能。
- **缓存**：当在服务端渲染组件时，可以缓存渲染结果，以便于在不同用户之间使用同样的内容，以达到提升性能。
- **初始页面加载与 FCP 指标显著提升**：通过提前在服务端生成 HTML 文件，用户可以立即看到你的内容而无需等待 JS 下载和执行。
- **SEO 搜索引擎优化**：搜索引擎机器人可以轻松读取由服务端生成的 HTML 文件，使网站更容易检索。
- **高效流式传输**：服务端组件能够分割渲染流程到不同的块（chunk）然后流式传输到客户端，可以更快查看页面，而不是等待整个页面在服务器上渲染



### RSC 服务端渲染 + Nextjs

除非明确指定，Next 将每一个组件视作服务器组件，而客户端组件则需要手动指定`"use client";`指令。

客户端组件重新加载页面时，会在服务端执行一次，以便于立即可以看到内容。

服务器端组件一直在服务端上渲染。



#### RSC 渲染生命周期

根据在浏览器，Nextjs 还有 React 三者之间的关系，来了解渲染的生命周期。但是生命周期分为 2 种

**1.在浏览器中请求页面（ RSC 加载序列）**

![image-20250813下午40026680](https://raw.githubusercontent.com/zyileven/image-hosting-platform/master/src/2025/08/13/f00043ac7f52db6e7dc7ae6790442c41-image-20250813下午40026680-e51612.png)

具体流程如下：

1. 浏览器请求页面；
2. 根据链接对应的地址，匹配到对应的服务端组件
3. react 渲染该服务端组件，以及他的所有子组件
4. react 将服务端组件渲染成一种特殊的 JSON 格式，称为 RSC 有效负载（RSC payload）
5. next 拿到 RSC payload 之后，同时使用 RSC 有效负载金和客户端组件指令在服务器上程程 HTML
6. 这些 HTML 会立即传输到浏览器，提供快速的**非交互式路由预览**
7. next 还会在 react 渲染每个 UI 时，传输 RSC payload
8. 浏览器开始逐步渲染 UI
9. 一旦所有客户端组件与服务器组件输出都已加载完成，就会呈现最终的 UI 给客户
10. 然后客户端组件在水合下将我们的应用程序从静态显示转换为交互式



**2.刷新浏览器（RSC 更新序列）**

![image-20250813下午40136588](https://raw.githubusercontent.com/zyileven/image-hosting-platform/master/src/2025/08/13/d1bf54e63fb5ab4e49e49e1ee1700ab0-image-20250813下午40136588-e6fdef.png)

流程如下：

1. 浏览器发起重新请求
2. 根据链接对应的地址，匹配到对应的服务端组件
3. react 渲染该服务端组件，以及他的所有子组件
4. react 将服务端组件渲染成一种特殊的 JSON 格式，称为 RSC 有效负载（RSC payload）
5. next 拿到 RSC payload 之后，传递给浏览器
6. 浏览器使用新内容触发路由的重新渲染
7. 然后仔细的协调或合并新的渲染输出与屏幕上的现有组件，因为我们使用的是特殊的 JSON 格式而不是 HTML
8. react 更新所有内容，并保持重要的 UI状态完整



### 服务器渲染策略

#### **静态渲染 Static rendering**

静态渲染是一种服务器渲染策略，旨在让我们在发布应用的 build 环节生成一些静态页面，一旦完成，这些页面就可以由 CDN 缓存并立即提供给用户。

并且，同一个与渲染页面可以在不同用户之间共享，从而显著提升你的应用性能。

所以，静态页面非常适合博客文章，电子商务产品列表，文档等页面。

##### 如何使用静态渲染呢？

- 静态渲染是默认策略
- 所有路由页面都会自动在构建时生成静态文件，无需任何额外的设置



#### **动态渲染 Dynamic rendering**

动态渲染是一种服务器渲染策略，当用户发生请求时，路由会为每一个用户发出唯一的渲染，一般用于个性化数据时比较有用。



##### 如何使用动态渲染？

- 当next 检测到我们使用了动态函数或者动态 AIP 的时候，next 会自动切换为动态渲染。
- 动态方法：
  - cookies()
  - headers()
  - connection()
  - draftMode()
  - searchParams prop
  - after()
- 强制动态渲染
  - 在顶部使用 `export const dynamic = "force-dynamic"`
